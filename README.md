# TermWatch

Windows PC の VS Code 統合ターミナルで動かすコーディングエージェント（Codex CLI など）を、
スマートフォンのブラウザからリアルタイムに**監視**し、必要なときだけ**操作**するための個人利用ツールです。

- PC 側のターミナルは今までどおり完全に使えます。
- 同じ出力をスマートフォンへリアルタイム配信します。
- スマートフォンは**既定で閲覧専用**です。操作は明示的に有効化したときだけ、一定時間だけ可能になります。
- 接続経路は **VS Code の Private Port Forwarding（Microsoft dev tunnels）限定**です。TermWatch 自身は
  インターネットへ何も公開しません。

## 動作要件

| 項目 | 内容 |
|---|---|
| OS | Windows 11（主対象）、Windows 10 22H2（可能な範囲） |
| アーキテクチャ | x64 |
| シェル | PowerShell / コマンドプロンプト / VS Code 統合ターミナル |
| リモート接続 | VS Code の Ports 機能（Microsoft dev tunnels）が利用できること |
| スマートフォン | iPhone Safari 最新版（主対象）。iPhone Chrome は可能な範囲で対応 |
| アカウント | GitHub または Microsoft アカウント（dev tunnels の認証に使用） |

ポータブル版には Node.js を同梱しているため、**PC への Node.js / npm のインストールは不要**です。

## インストール（ポータブル版）

1. `TermWatch-win-x64.zip` を任意のフォルダーへ展開します。
2. 展開したフォルダーの中で `termwatch.cmd` を実行します。

```text
TermWatch-win-x64/
├─ termwatch.cmd      … 起動スクリプト（コマンドプロンプト／PowerShell 共通）
├─ runtime/node.exe   … 同梱の Node.js ランタイム
├─ app/               … TermWatch 本体
├─ web/               … スマートフォン向け Web UI
├─ node_modules/      … node-pty などの実行時依存（ネイティブモジュール含む）
├─ LICENSES/
└─ README.md
```

- システムサービスの登録、レジストリの変更は一切行いません。
- **アンインストールは展開したフォルダーを削除するだけ**で完了します。

### 起動方法

TermWatch は**引数を付けてターミナルから実行する**ツールです。
`termwatch.cmd` をエクスプローラーからダブルクリックするとヘルプを表示して停止します
（実行するコマンドが指定されていないため）。

VS Code の統合ターミナル（PowerShell）から、次のいずれかで実行してください。

**方法 A: フルパスで実行する（設定不要）**

```powershell
& "C:\tools\TermWatch\termwatch.cmd" -- codex
```

**方法 B: フォルダーへ移動して実行する**

```powershell
cd C:\tools\TermWatch
.\termwatch.cmd -- codex
```

**方法 C: `termwatch` とだけ入力できるようにする（推奨・PATH へ追加）**

現在のターミナルだけで有効にする場合:

```powershell
$env:Path = "$env:Path;C:\tools\TermWatch"
termwatch -- codex
```

以後ずっと有効にする場合（ユーザー環境変数へ追加。**VS Code の再起動が必要**）:

```powershell
[Environment]::SetEnvironmentVariable(
  'Path',
  [Environment]::GetEnvironmentVariable('Path', 'User') + ';C:\tools\TermWatch',
  'User'
)
```

> `C:\tools\TermWatch` は ZIP を展開した実際のパスに読み替えてください。
> `dist\` 配下はビルドのたびに作り直されるため、**PATH には `dist\` ではなく
> 安定した場所（例: `C:\tools\TermWatch`）を登録**することを推奨します。
> PATH を変更したあとは、**VS Code を完全に終了して起動し直す**と反映されます
> （ターミナルを開き直すだけでは反映されないことがあります）。

以降、このドキュメントでは `termwatch` と表記しますが、上記いずれかの方法に読み替えてください。

### Git Bash から使う場合

Git Bash（MinTTY）は Windows ネイティブプログラムの標準入出力をコンソールではなく
パイプとして渡すため、**そのままでは Codex などのフルスクリーン TUI を操作できません**
（キー入力の転送と端末サイズの取得ができないため）。TermWatch はこの状態を検出して
起動時に警告を表示します。

また Git Bash は PATH 解決時に `.cmd` を補完しないため、`termwatch` ではなく
**`termwatch.cmd`** と入力する必要があります。

Git Bash から使う場合は `winpty` を挟んでください。

```bash
winpty termwatch.cmd -- codex
```

**PowerShell / コマンドプロンプト / VS Code 統合ターミナルからの起動を推奨します。**

## 使い方

```text
termwatch [オプション] -- <実行コマンド> [引数...]
```

`--` より後ろは一切解釈せず、そのまま子プロセスへ渡します。

### 例

```powershell
# Codex CLI を起動して監視する
termwatch -- codex

# 直前の Codex セッションを再開して監視する
termwatch -- codex resume --last

# 他の CLI エージェント
termwatch -- claude
termwatch -- gemini

# 作業フォルダーとポートを指定する
termwatch --cwd "C:\work\my project" --port 43821 -- codex

# ローカル実行のみ（スマートフォン接続を無効化）
termwatch --local-only -- codex
```

### オプション

| オプション | 既定値 | 内容 |
|---|---:|---|
| `--cwd <path>` | 現在のフォルダー | 子プロセスの作業フォルダー |
| `--port <number>` | `43821` | ローカル Web サーバーのポート |
| `--buffer-lines <number>` | `10000` | 再接続用に保持する最大表示行数 |
| `--control-minutes <number>` | `10` | スマートフォン操作権の有効時間（分） |
| `--record <path>` | 無効 | 指定時のみ生 PTY 出力をファイルへ保存 |
| `--local-only` | 無効 | スマートフォン接続を無効化 |
| `--help`, `-h` | - | ヘルプ表示 |
| `--version`, `-v` | - | バージョン表示 |

ポートが使用中の場合、TermWatch は**勝手に別のポートへ変更しません**。エラーを表示して終了するので、
`--port` で別のポートを指定してください。

## スマートフォンから接続する

TermWatch の Web サーバーは **`127.0.0.1` だけ**で待ち受けます。LAN や
インターネットからは直接到達できません。スマートフォンからは VS Code の
Private Port Forwarding を経由して接続します。

1. **TermWatch を起動する**

   ```powershell
   termwatch -- codex
   ```

   PC 側ターミナルにペアリングコード（例: `A7KP-3M9X`）が表示されます。

2. **VS Code で Ports ビューを開く**

   コマンドパレット（`Ctrl+Shift+P`）で `Ports: Focus on Ports View` を実行します。

3. **ポートを転送する**

   `Forward a Port` を選び、`43821`（`--port` を変えた場合はその番号）を入力します。

4. **Port Visibility が `Private` であることを確認する**

   一覧の Visibility 列が `Private` であることを必ず確認してください。
   **`Public` へ変更しないでください。** Public にすると、URL を知る誰でもターミナル内容へ
   到達できる状態になります。TermWatch は Public への変更を案内も自動実行もしません。

5. **Forwarded Address をスマートフォンで開く**

   一覧に表示される `https://xxxx-43821.<region>.devtunnels.ms` のような URL を、
   スマートフォンの Safari で開きます（URL のコピーには VS Code の「Copy Local Address」を使うと簡単です）。

6. **GitHub または Microsoft アカウントで認証する**

   PC 側で転送を開始したものと**同じアカウント**でサインインします。

7. **ペアリングコードを入力する**

   TermWatch の画面が開くので、手順 1 で PC 側に表示されたペアリングコードを入力します。
   ハイフンや小文字はそのまま入力して構いません。

   ペアリングコードは **起動から 10 分、または最初の認証成功のいずれか早い方**で失効します。
   失効した場合は TermWatch を起動し直してください。

接続後は、スマートフォンのブラウザを閉じたり画面ロックしたりしても子プロセスは動き続けます。
復帰すると自動的に再接続し、直近の出力が復元されます。

## 閲覧モードと操作モード

### 閲覧モード（既定）

- 出力の閲覧、スクロール、コピーだけができます。
- PTY への入力は一切できません。これはサーバー側で強制しているため、
  ブラウザの開発者ツールで UI を書き換えたり、WebSocket メッセージを直接送ったりしても入力はできません。

### 操作モード

1. 画面下部の「操作モードにする」をタップします。
2. 確認ダイアログで「有効にする」を選びます。
3. 既定で **10 分間**、この端末から入力できるようになります（`--control-minutes` で変更可）。

- 残り時間は画面上部に常時表示されます。
- 残り 1 分で警告表示に変わります。
- 期限到達で自動的に閲覧モードへ戻ります。
- 「閲覧モードに戻す」でいつでも即時解除できます。
- 通信が **60 秒以上**切断されたままだと自動解除されます。
- **同時に操作権を持てる端末は 1 台だけ**です。他の端末は閲覧専用のまま接続できます。
- **PC 側のキーボード入力は常に有効**です。操作モード中でも PC 側が優先されます。
  PC 入力とスマートフォン入力は、PTY に届いた順番どおりに書き込まれます。

操作モードが有効な間、PC 側はウィンドウタイトルが `TermWatch: <コマンド> [リモート操作モード有効]`
に変わります。ターミナル画面そのものには何も書き込まないため、Codex などの TUI 表示を壊しません。

### 入力方法

- 複数行テキストエリアに指示を入力し、「送信」ボタンで一括送信します。
  途中の改行で誤送信されないよう、複数行のテキストは bracketed paste として送信し、
  最後に Enter を送ります。
- 特殊キーバーから `Enter` `Esc` `Tab` `↑` `↓` `←` `→` `y` `n` `Ctrl+C` を送れます。
- 送信履歴はブラウザのメモリ上（現在のセッション内）だけに保持され、保存されません。

---

## Ctrl+C の注意点

`Ctrl+C` は危険操作として赤字で表示され、タップ後に確認ダイアログが出ます。

- Ctrl+C は操作元にかかわらず**子プロセスへ転送**されます。
- 実行中の処理が中断されたり、CLI エージェント自体が終了したりする場合があります。
- 子プロセスが終了すると TermWatch も終了するため、リモートからの再開はできません。
  再度 TermWatch を起動する必要があります。

---

## ログの取り扱い

- **既定ではターミナル内容をディスクへ保存しません。** 出力はメモリ上のリングバッファ
  （既定 10,000 表示行）にだけ保持され、TermWatch の終了時に破棄されます。
- `--record <path>` を指定したときだけ、生の PTY 出力を指定ファイルへ追記保存します。

`--record` を使う場合の注意:

- 保存されるのは**画面に出た内容そのまま**です。APIキー、パスワード、ソースコードなどが
  含まれる可能性があります。
- ANSI エスケープシーケンスを含む生データのため、テキストエディターでは読みにくい場合があります。
- 保存先のアクセス権とバックアップ対象（クラウド同期フォルダーなど）に注意してください。
- 不要になったら削除してください。

セッショントークンとペアリングコードは、`--record` の保存対象にも通常ログにも含まれません。

## セキュリティ上の約束

TermWatch は次のことを**行いません**。

- `0.0.0.0` や LAN IP での待ち受け
- LAN への自動公開
- VS Code の Public Port Forwarding の案内・自動実行
- ngrok などの公開トンネルへの自動接続
- ルーターのポート開放や Windows ファイアウォールの受信許可ルール追加の要求
- dev tunnel の作成・削除・公開範囲変更の自動実行
- 認証前のターミナル出力配信
- セッショントークンやペアリングコードのログ・URL への出力
- 既定での PTY 出力のファイル保存
- 子プロセスの管理者権限実行（TermWatch を起動したユーザーと同じ権限で動きます）

詳細は [SECURITY.md](SECURITY.md) を参照してください。

## 終了方法

- **子プロセスを終了させるのが基本**です（多くの CLI では `/exit`、`exit`、`Ctrl+C` など）。
  子プロセスが終了すると、TermWatch はその終了コードを自分の終了コードとして返して終了します。
- 終了コードは PC 側とスマートフォン側の両方に表示されます。
- 終了通知を送るため最大 3 秒待ってから終了します。
- PC 側ターミナルを閉じた場合、子プロセスも終了します（孤児プロセスを残しません）。
- 終了時に、セッショントークンの無効化、WebSocket の切断、メモリ上の出力バッファの破棄、
  ターミナルの raw mode / カーソル状態の復元を行います。

## トラブルシューティング

### ポートが使用中と表示される

```text
ポート 43821 は既に使用されています。
```

別のアプリ（あるいは起動済みの TermWatch）が使用しています。`--port 43822` のように
別のポートを指定してください。VS Code の Ports ビューでもそのポート番号を転送してください。

### `'termwatch' は、内部コマンドまたは外部コマンド...として認識されていません`

ポータブル版のフォルダーが PATH に入っていません。
[起動方法](#起動方法) の方法 A〜C のいずれかを使ってください。

### `termwatch.cmd` をダブルクリックすると一瞬でウィンドウが閉じる

実行するコマンドを指定していないためです。TermWatch は
`termwatch -- codex` のように**引数付きでターミナルから**実行してください。
（ダブルクリック時はヘルプを表示して停止するようになっています。）

### Git Bash で `termwatch: command not found` になる

Git Bash は PATH 解決時に `.cmd` を補完しません。`termwatch.cmd` と入力してください。
さらに TUI を操作するには `winpty termwatch.cmd -- codex` のように `winpty` を挟む必要があります。
[Git Bash から使う場合](#git-bash-から使う場合) を参照してください。

### 実行コマンドが見つからない

```text
実行コマンドが見つかりません: codex
```

`codex` に PATH が通っているか確認してください。VS Code を起動したあとに CLI をインストールした場合は、
ターミナルを開き直すと PATH が反映されます。

### スマートフォンで「接続できません」と表示される

- VS Code の Ports ビューでポートが転送されたままか確認してください（VS Code を閉じると転送も止まります）。
- TermWatch が起動したままか確認してください。
- スマートフォンが PC と同じ GitHub / Microsoft アカウントで認証されているか確認してください。

### ペアリングコードが通らない

- コードは **10 分**、または**最初の認証成功**で失効します。TermWatch を起動し直してください。
- 認証に連続して失敗するとレート制限がかかり、一時的に受け付けなくなります。
  表示される待ち時間だけ待ってから再試行してください。

### 「OriginとHostが一致しません」で接続できない（403）

TermWatch は同一オリジン以外からの WebSocket 接続を拒否します。安全側に倒しているため、
プロキシ構成によっては拒否されることがあります。次を確認してください。

- 転送 URL（`https://...devtunnels.ms`）を**直接**開いていること（別サイトからの埋め込みや
  リダイレクト経由ではないこと）。
- ブラウザの拡張機能が Origin ヘッダーを書き換えていないこと。

この制限を緩める設定は用意していません。安全性を下げる回避策は提供しません。

### 組織のポリシーで dev tunnels が使えない

Microsoft dev tunnels が組織のポリシーやネットワークで禁止されている場合、
**TermWatch のリモート機能は利用できません**。TermWatch は LAN 公開などへ自動フォールバックしません。
その場合は `--local-only` を付けてローカル実行だけを行ってください。

### 日本語が文字化けする

VS Code 統合ターミナルのフォント設定と、CLI 側のエンコード設定を確認してください。
TermWatch は PTY のデータをそのまま転送するため、PC 側で正しく表示できていればスマートフォン側でも同じように表示されます。

## 既知の制約

- 既に起動している VS Code ターミナルへの後付け接続はできません。TermWatch 経由で起動する必要があります。
- スマートフォン側から端末サイズは変更できません（PC 側のサイズが常に正）。
  スマートフォンでは縮小表示・折り返し・横スクロールで対応します。
- 出力内容を解析して「承認待ち」「質問待ち」などを判定しません。表示するのは
  「起動中／実行中／出力停止中／終了／再接続中／PC未接続」の観測可能な状態と、最終出力からの経過時間だけです。
  **「出力停止中」は「入力待ち」を意味しません。**
- 複数行送信は bracketed paste を使用します。対応していない TUI では、
  `[200~` のような文字が入力欄に現れる場合があります。その場合は 1 行ずつ送信してください。
- iOS のプッシュ通知、Android 実機検証、複数ターミナルの切り替えは対象外です。
- ポータブル版は Windows x64 専用です。
- Git Bash（MinTTY）からは `winpty` を挟まないと TUI を操作できません。
  また `termwatch` ではなく `termwatch.cmd` と入力する必要があります。

## 開発者向け

```powershell
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npm run package:win
```

| スクリプト | 内容 |
|---|---|
| `npm run typecheck` | サーバー側と Web UI の型チェック |
| `npm run lint` | ESLint |
| `npm test` | 単体テスト＋統合テスト（vitest） |
| `npm run build` | `dist/app`（サーバー）と `dist/web`（Web UI）を生成 |
| `npm run package:win` | `dist/TermWatch-win-x64/` と `.zip` を生成 |
| `npm run install:local` | ポータブル版を常用フォルダー（既定 `C:\tools\TermWatch`）へ配置 |
| `npm run release:local` | build → package:win → install:local をまとめて実行 |

`install:local` の配置先は環境変数 `TERMWATCH_INSTALL_DIR` で変更できます。
PATH の設定は行わないため、初回だけ上記「方法 C」を実行してください。
以降はコードを変更しても `npm run release:local` だけで反映されます。
