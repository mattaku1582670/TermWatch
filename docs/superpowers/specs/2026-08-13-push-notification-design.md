# プッシュ通知 設計

作成日: 2026-08-13 ／ 状態: 承認済み

## 背景

TermWatch の MVP は完了している。本機能は要件定義書 第18章「将来拡張候補」の
「出力停止・終了時の通知」にあたる。同 第4章では iOS プッシュ通知を対象外と
していたため、**要件定義書の範囲を意図的に超える追加**である。

外出先から Codex を監視する用途では、作業が終わったことに気づけないと
画面を定期的に開いて確認することになる。これを解消する。

## 目的と非目的

**目的**: 子プロセスの出力が一定時間止まったことを iPhone へ通知する。

**非目的**:

- 出力内容の解析による「承認待ち」などの意味判定（要件定義書 第4章で対象外）
- ターミナル内容の外部送信
- 独自の中継サーバー（要件定義書 第4章で対象外）
- Android 実機対応

## 前提

- 通知経路は Web Push（Apple のプッシュ網）。iOS で画面を閉じた状態へ届ける
  手段はこれ以外に無い。本文は端末間で暗号化され、Apple にも読めない。
- iOS の制約により、**ホーム画面へ追加した場合のみ**通知を受け取れる。
  Safari のタブのままでは動作しない。
- 購読はオリジン（転送 URL）に紐づく。利用者の環境では VS Code の転送 URL が
  再利用されることを確認済みのため、登録し直しは通常発生しない。
  URL が変わった場合は再登録が必要になる。

## 構成

```
[PTY出力] → IdleWatcher ─(既定30秒静止)→ PushSender ─暗号化─> Apple ─> iPhone
                 ↑                            ↑
            出力のたびに                  SubscriptionStore
             タイマー再開                （ファイルへ永続化）
```

| モジュール | 役割 | 依存 |
|---|---|---|
| `src/notify/idle-watcher.ts` | 出力停止の検知。しきい値到達で1回だけ発火する | なし（時刻とイベントのみ） |
| `src/notify/subscription-store.ts` | 購読情報の読み書き。権限 0600 | `node:fs` |
| `src/notify/push-sender.ts` | VAPID 鍵の生成・保管、送信 | `web-push` |

いずれも既存モジュールから独立させ、単体で試験できる形にする。
`PtySession` と `TermWatchServer` への変更は接続部分に限る。

## 動作

### 検知

`PtySession` の `data` イベントごとにタイマーを再開する。
しきい値（既定 30 秒）に達したら通知を1件送る。

UI の「出力停止中」判定（`IDLE_THRESHOLD_MS` = 3 秒）とは別の値にする。
3 秒は入力を考えている間にも成立するため、通知には短すぎる。

### 抑制

以下のいずれかに当てはまるときは送らない。

1. **同じ静止期間で既に送信済み** — 出力が再開するまで再通知しない。
2. **接続中の端末がある** — 認証済み WebSocket 接続が1つでもあれば送らない。
   端末は区別しない（PCのブラウザで開いている場合や、別の端末が接続している
   場合も含む）。iOS では画面を閉じると WebSocket が切れるため、
   iPhone側についてはこれで「見ている間」を判定できるが、
   判定そのものは接続数だけを見ており、特定の端末を識別してはいない。
3. **購読が無い** — 機能は購読するまで完全に不活性。

### 通知内容

```
TermWatch
codex の出力が30秒止まっています
```

コマンド名と経過時間のみ。**ターミナルの内容は含めない。**
タップすると TermWatch の画面を開く。

## API

いずれも既存のセッション認証を通す。未認証は 401。Origin 検証は状態を変更する
POST / DELETE にのみ課す（GET /api/session と同様、同一オリジンの GET には
ブラウザが Origin ヘッダーを付けないため）。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/push/key` | VAPID 公開鍵を返す |
| POST | `/api/push/subscribe` | 購読情報を保存する |
| DELETE | `/api/push/subscribe` | 購読を解除する（将来のUI追加に備えて残す。現状これを呼ぶUIはない） |

## Web 側

- `manifest.json` — ホーム画面追加用
- Service Worker — `push` と `notificationclick` を処理する
- 「通知を有効にする」ボタン（有効化のみ。解除するUIは設けない）
  iOS では利用者の操作が起点でないと許可を求められないため、
  ページ読み込み時に自動で要求してはならない。

## CLI

```
--notify-idle-seconds <秒>   通知までの静止時間（既定: 30）
--no-notify                  通知機能を無効化
```

## 保存するもの

`%APPDATA%\TermWatch\` に以下を置く。権限は 0600。

| ファイル | 内容 |
|---|---|
| `vapid.json` | VAPID 鍵ペア。初回起動時に生成する |
| `subscriptions.json` | 購読情報 |

これは TermWatch にとって初めての永続状態になる。
ターミナル内容は含まない（`--record` の方針は変えない）。

## セキュリティ

| 項目 | 方針 |
|---|---|
| 通知本文 | ターミナル内容を含めない |
| 購読情報・VAPID 秘密鍵 | 権限 0600。ログ・URL・エラー出力へ一切出さない |
| 購読 API | セッション認証と Origin 検証。未認証は拒否 |
| バインドアドレス | 変更しない（`127.0.0.1` のまま） |
| 送信先 | Apple のプッシュ網のみ。独自中継は作らない |

## 依存関係

`web-push` を追加する。

Web Push の暗号化（RFC 8291）は ECDH・HKDF・AES-128-GCM の組み合わせで、
自前実装は誤ると通知が届かないだけでなく暗号の強度を損なう。
現在の依存は `ws` と `node-pty` の2つだけであり、増やす判断は慎重に行ったが、
暗号処理の自前実装より安全と判断した。

## 試験

**自動化する**

- 静止判定のタイミング（発火する・しない・再開でリセット）
- 抑制条件（重複送信しない、接続中は送らない、購読なしで送らない）
- 通知本文にターミナル内容が混ざらないこと
- 未認証の購読要求を拒否すること
- 購読情報がログへ出ないこと

**自動化できない**

Apple への実配信。手動確認 MT-18 として `docs/MANUAL_TESTS_WINDOWS.md` に追加する。

## 未解決の点

- 転送 URL が変わった場合、購読は無効になる。再登録の案内を UI に出すかは
  実装時に判断する（失効した購読は送信時に 410 が返るため検出できる）。
