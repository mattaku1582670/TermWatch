# 受け入れ基準の確認結果

`TermWatch_Requirements_v1.0.md` 第 15 章の受け入れ基準 18 項目について、
実装時点での確認結果を記録する。

- 確認日: 2026-08-10
- 確認環境: Windows 11 Enterprise 10.0.26200 / Node.js v24.14.0 / x64
- 実施した自動検証: `npm ci`、`npm run lint`、`npm run typecheck`、`npm test`（111 件）、`npm run build`、`npm run package:win`
- 外部コードレビュー（Codex）を実施し、指摘のうちバグ・セキュリティ該当分を修正済み（`docs/DECISIONS.md` D-015）
- **未実施**: iPhone 実機、VS Code Port Forwarding、Codex CLI での実行、Node.js 未導入 PC での展開

判定の意味:

| 記号 | 意味 |
|---|---|
| 合格 | この環境で実際に確認できた |
| 未確認 | 実装済みだが、必要な実機・外部サービスが無いため未検証 |
| 不合格 | 確認して満たせなかった |

**「実装したから合格」とは扱っていない。** 実行して確認したものだけを合格としている。

| # | 受け入れ基準 | 判定 | 根拠・備考 |
|---|---|---|---|
| 1 | VS Code ターミナルから `termwatch -- codex` で Codex を起動できる | **未確認** | Codex CLI が本環境に無いため未検証。代わりに `node`（PTY 内）を子プロセスとして起動し、CLI 引数の受け渡し（`-- <cmd> [args]`）と PTY 起動を確認済み（`tests/integration/pty-session.test.ts`、ポータブル版の実行確認）。`.cmd` シム経由の起動経路は実装済みだが未検証。手順は MT-01 |
| 2 | PC 側で通常どおり Codex へ日本語入力できる | **未確認** | 日本語文字列の PTY 往復は自動テストで確認済み（`ローカル入力をPTYへ転送し、応答が返る`）。VS Code 統合ターミナル＋IME での実操作は未検証。手順は MT-01 |
| 3 | ポート 43821 を Private 転送し、認証した iPhone からペアリングコードで接続できる | **未確認** | ペアリング API（Origin 検証・コード検証・Cookie 発行）はローカルで実行確認済み。dev tunnels 経由は未検証。Origin 検証が実環境で通るかは `docs/DECISIONS.md` D-005 の未確認事項。手順は MT-04 |
| 4 | iPhone に ANSI カラー付き出力が概ね 500ms 以内で表示される | **未確認** | ローカルでは PTY 出力から WebSocket 配信までミリ秒単位。実回線での測定は未実施。手順は MT-05 |
| 5 | iPhone 切断後も Codex が動作し続ける | **合格** | 統合テスト `WebSocket切断後も子プロセスは動き続ける` で確認 |
| 6 | iPhone 再接続時に直近 10,000 行が復元される | **合格**（機構） | 統合テスト `再接続時に受信済み以降だけを受け取る`、単体テスト（リングバッファ上限・truncated 通知）で確認。既定 10,000 表示行はチャンク境界での近似保持（D-002）。iPhone 実機での復元表示は未確認 |
| 7 | 閲覧モードでは改変した WebSocket リクエストでも PTY 入力されない | **合格** | 統合テスト `閲覧モードでは直接WebSocketメッセージを送っても入力されない`。サーバー側で操作権を検査 |
| 8 | 操作モードで複数行の日本語指示を一括送信できる | **合格**（機構） | 統合テスト `操作モードでは入力がPTYへ届く`、単体テスト `encodeTextInput`（bracketed paste・CRLF 正規化）で確認。Codex TUI での実挙動は未確認（MT-09） |
| 9 | Enter、Esc、Tab、Ctrl+C、方向キー、y、n が機能する | **合格**（エンコード） | 単体テスト `特殊キーのエンコード` で全 10 キーのバイト列を確認。Codex 上での実動作は未確認（MT-10） |
| 10 | 操作モードが 10 分後に自動解除される | **合格** | 単体テスト `期限到達で自動解除する`、`残り1分で1度だけ警告する`、`60秒以上の切断で操作権を解除する` |
| 11 | 同時に 2 台が接続しても操作権を持てるのは 1 台だけ | **合格** | 統合テスト `操作権は1台だけが保持できる`、単体テスト `同時に保持できるのは1台だけ` |
| 12 | スマートフォン接続によって PC 側のターミナルサイズが変化しない | **合格**（設計） | リサイズ要求はプロトコルに存在せず、スキーマ検証で未知の type は拒否される（単体テスト `未知のtypeを拒否する` で `resize` を明示的に検証）。PTY のリサイズは `LocalIo` の `stdout` の resize イベントからのみ呼ばれる。実機での目視確認は未実施（MT-13） |
| 13 | 子プロセス終了時に終了コードが PC 側とスマートフォン側へ表示される | **合格** | 統合テスト `子プロセス終了時に終了コードを通知する`（WebSocket 側）、`子プロセスの終了コードを伝える`（PTY 側）、ポータブル版実行で終了コード 5 の伝播を確認。UI 表示部は実装済み・実機未確認 |
| 14 | 無効なセッショントークンでは出力を取得できない | **合格** | 統合テスト `認証前はWebSocketに接続できない`、`無効なトークンでは接続できない`、`認証済みクライアントだけが出力を取得できる` |
| 15 | TermWatch が `0.0.0.0` や LAN IP で待ち受けていない | **合格** | 実起動して `netstat -ano` で確認: `TCP 127.0.0.1:43899 ... LISTENING` のみ。コード上も `listen(port, '127.0.0.1')` 固定 |
| 16 | dev tunnels が利用できない場合も LAN や `0.0.0.0` へ自動公開されない | **合格**（設計） | bind アドレスは `127.0.0.1` のハードコードで、変更する設定・分岐が存在しない。フォールバック処理も存在しない。dev tunnels 遮断環境での実挙動は未確認（MT-15） |
| 17 | `--record` 未指定時にターミナル内容がディスクへ保存されない | **合格** | 統合テスト `--record 指定時のみディスクへ保存する`。`--record` が null のとき書き込みストリームを一切生成しない |
| 18 | ZIP 展開後、Node.js を別途インストールせず起動できる | **一部合格** | ZIP を展開し、同梱 `runtime\node.exe` から `--version`・PTY 経由の子プロセス実行・終了コード伝播を確認済み。ただし**確認は Node.js 導入済みの開発機上**であり、Node.js 未導入の別 PC での確認は未実施（MT-14） |
