# 受け入れ基準の確認結果

`TermWatch_Requirements_v1.0.md` 第 15 章の受け入れ基準 18 項目について、
実装時点での確認結果を記録する。

- 初回記録: 2026-08-10 ／ 最終更新: 2026-08-11
- 確認環境: Windows 11 Enterprise 10.0.26200 / Node.js v24.14.0 / x64 / iPhone Safari / VS Code Private Port Forwarding
- 実施した自動検証: `npm ci`、`npm run lint`、`npm run typecheck`、`npm test`（120 件）、`npm run build`、`npm run package:win`
- 外部コードレビュー（Codex）を実施し、指摘のうちバグ・セキュリティ該当分を修正済み（`docs/DECISIONS.md` D-015）
- 実施済みの手動確認: MT-01、MT-02、MT-04、MT-05、MT-07、MT-13、MT-17（MT-09・MT-10 は一部）
- **未実施**: MT-14（Node.js 未導入 PC）、MT-15（障害系）
- **再確認待ち**: MT-09（複数行送信の確定）、MT-10（Ctrl+C 以外の特殊キー）

判定の意味:

| 記号 | 意味 |
|---|---|
| 合格 | この環境で実際に確認できた |
| 未確認 | 実装済みだが、必要な実機・外部サービスが無いため未検証 |
| 不合格 | 確認して満たせなかった |

**「実装したから合格」とは扱っていない。** 実行して確認したものだけを合格としている。

| 14 | 無効なセッショントークンでは出力を取得できない | **合格** | 統合テスト `認証前はWebSocketに接続できない`、`無効なトークンでは接続できない`、`認証済みクライアントだけが出力を取得できる` |

| 16 | dev tunnels が利用できない場合も LAN や `0.0.0.0` へ自動公開されない | **合格**（設計） | bind アドレスは `127.0.0.1` のハードコードで、変更する設定・分岐が存在しない。フォールバック処理も存在しない。dev tunnels 遮断環境での実挙動は未確認（MT-15） |

## 集計

| 判定 | 件数 | 該当項目 |
|---|---:|---|
| 合格 | 16 | 1〜7, 9〜17 |
| 一部合格 | 1 | 18 |
| 再確認待ち | 1 | 8 |
| 不合格 | 0 | - |

補足: 9 は Ctrl+C と Enter のみ実機確認済みで、残りのキーは未確認（MT-10）。
16 は設計上の確認にとどまり、dev tunnels 遮断環境での実挙動は未確認（MT-15）。
8 は修正を重ねた結果、実機での最終確認が必要な状態にある。
18 は Node.js 導入済みの開発機での展開・実行のみ確認しており、
Node.js 未導入 PC での確認（MT-14）が残っている。

### 実機確認で見つかり、修正した不具合

| 発見 | 内容 | 対応 |
|---|---|---|
| MT-09 (1) | 複数行の指示が改行位置で分割され、2 つの指示として渡っていた | bracketed paste 内の改行を CR → LF（`7386e78`） |
| MT-09 (2) | 入力はされるが確定されず、追加の Enter が必要だった | 確定の CR を本文とは別の書き込みで送る |
| MT-09 (3) | (2) の修正で単一行が確定しなくなる退行 | 固定時間待ちをやめ、TUI の再描画を検知してから確定する方式へ |
| MT-17 | キーボード表示時に入力欄が画面外へ押し上げられ、下に空白が出る | body をビューポートへ固定し、ページ全体のスクロールを止めた |
| MT-02 | 再ペアリング時、ペアリングコードが子プロセスの画面消去で読めなくなっていた | ウィンドウタイトルへも表示（`05b6b0b`） |
| 起動 | `termwatch.ps1` が PowerShell の実行ポリシーで弾かれ、PATH 経由で起動できなかった | `.ps1` を同梱しない（D-016） |
