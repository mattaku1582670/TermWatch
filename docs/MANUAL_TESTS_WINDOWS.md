# 手動確認手順（Windows / iPhone / VS Code Port Forwarding）

自動テストで検証できない項目をここにまとめる。実機（Windows PC・iPhone・VS Code の Ports 機能）が
必要なため、開発時点では**未実施**である。実施したら結果を `docs/ACCEPTANCE_RESULTS.md` へ反映すること。

各項目は「手順 → 期待結果 → 不合格の目安」の形式で記述する。

---

## 前提

- Windows 11 x64
- VS Code（Ports ビューが使えること／組織ポリシーで dev tunnels が禁止されていないこと）
- GitHub または Microsoft アカウント
- iPhone（Safari 最新版）
- Codex CLI が PATH 上にあること

準備:

```powershell
cd C:\Users\<you>\Development\TermWatch
npm ci
npm run build
npm run package:win
```

以降、`termwatch` は `dist\TermWatch-win-x64\termwatch.cmd` を指す。

---

## MT-01: Codex を起動して通常どおり使える

1. VS Code の統合ターミナルで `termwatch -- codex` を実行する。
2. 起動バナーとペアリングコードが表示されることを確認する。
3. Codex の TUI が通常どおり表示されることを確認する。
4. PC のキーボードから日本語で指示を入力し、送信する。

**期待結果**: TermWatch を挟まない場合と同じように Codex が動作し、日本語入力・変換・
ANSI カラー・カーソル移動・プログレス表示が崩れない。

**不合格の目安**: 文字化け、TUI の描画崩れ、入力の取りこぼし、体感できる入力遅延。

---

## MT-02: `codex resume --last` で再開できる

1. MT-01 のセッションを終了する。
2. `termwatch -- codex resume --last` を実行する。

**期待結果**: 直前のセッションが復元される。`--last` が TermWatch に解釈されず、
そのまま Codex へ渡っている。

---

## MT-03: 大量出力時にローカル操作性が保たれる

1. `termwatch -- codex` を起動し、大量の出力を発生させる（大きなファイルの表示など）。
2. 出力中に PC 側でキー入力する。

**期待結果**: 出力中も PC 側の入力が滞らない。TermWatch の CPU 使用率が異常に上がらない。

---

## MT-04: VS Code の Private Port Forwarding で iPhone から接続できる

1. `termwatch -- codex` を起動する。
2. コマンドパレットで `Ports: Focus on Ports View` を実行する。
3. `Forward a Port` で `43821` を転送する。
4. **Visibility が `Private`** であることを確認する。
5. Forwarded Address を iPhone の Safari で開く。
6. PC と同じ GitHub / Microsoft アカウントでサインインする。
7. TermWatch のペアリング画面が表示されたら、PC 側のペアリングコードを入力する。

**期待結果**: 接続でき、閲覧モードで PC と同じ内容が表示される。

**不合格の目安**: 403（Origin 不一致）で WebSocket が繋がらない。
→ その場合は `docs/DECISIONS.md` D-005 の未確認事項に該当する。ブラウザの開発者ツールで
実際の `Host` / `Origin` / `X-Forwarded-Host` を確認し、報告すること。

---

## MT-05: 表示遅延が 500ms 未満

1. MT-04 の状態で、PC 側で `Get-Date -Format o` のように現在時刻を出力する。
2. PC 画面と iPhone 画面を同時に撮影する（動画推奨）。

**期待結果**: 出力から iPhone 表示までの遅延の中央値が 500ms 未満。

---

## MT-06: iPhone 切断後も Codex が動き続ける

1. MT-04 の状態で、iPhone の Safari を閉じる／機内モードにする。
2. PC 側で Codex を操作する。

**期待結果**: Codex は影響を受けず動作し続ける。TermWatch も終了しない。

---

## MT-07: 再接続で直近の出力が復元される

1. MT-06 の状態から iPhone の通信を復帰させ、Safari を開く。

**期待結果**: 自動的に再接続し（指数バックオフ）、切断中の出力を含めて表示が復元される。
バッファ上限を超えていた場合は「バッファ上限のため、これより古い出力は破棄されています」と表示される。

---

## MT-08: 閲覧モードでは入力できない

1. iPhone の Safari で開発者ツール（Mac の Safari からリモートインスペクタ）を接続する。
2. コンソールから WebSocket へ直接 `{"type":"input.text","text":"test","submit":true}` を送る。

**期待結果**: PTY へは何も入力されず、`error` / `forbidden` が返る。

**注記**: 同等の検証は自動統合テストでも実施済み（`tests/integration/server.test.ts`）。

---

## MT-09: 操作モードで複数行の日本語指示を一括送信できる

1. iPhone で「操作モードにする」→ 確認ダイアログで有効化する。
2. テキストエリアへ日本語 IME で複数行の指示を入力する。
3. 「送信」をタップする。

**期待結果**: 途中の改行で分割されず、全体が 1 つの指示として Codex に渡り、最後に Enter が送られる。

**不合格の目安**: 1 行目だけが送信される／`[200~` のような文字列がそのまま表示される
（後者は bracketed paste 非対応。DECISIONS D-007 のフォールバック該当）。

---

## MT-10: 特殊キーが機能する

操作モードで以下を 1 つずつ試す。

| キー | 期待結果 |
|---|---|
| `Enter` | 改行・確定として扱われる |
| `Esc` | Codex のダイアログや入力がキャンセルされる |
| `Tab` | 補完が働く |
| `↑` `↓` | 履歴・選択肢の移動 |
| `←` `→` | カーソル移動 |
| `y` `n` | 確認プロンプトへの応答 |
| `Ctrl+C` | 確認ダイアログが出て、実行すると子プロセスへ SIGINT 相当が届く |

## MT-11: 操作モードが自動解除される

1. `termwatch --control-minutes 2 -- codex` で起動する（確認短縮のため 2 分）。
2. iPhone で操作モードを有効化する。
3. 残り 1 分の表示と警告色を確認する。
4. 2 分経過するまで待つ。

**期待結果**: 残り時間が常時表示され、残り 1 分で赤字になり、期限で自動的に閲覧モードへ戻る。

追加確認: 操作モード中に iPhone を機内モードにして 60 秒以上放置すると、
復帰時に操作権が解除されている（60 秒未満なら維持される）。

---

## MT-12: 2 台同時接続で操作権は 1 台だけ

1. iPhone と別の端末（iPad / PC のブラウザ）の両方で転送 URL を開き、ペアリングする。
   ※ ペアリングコードは最初の認証成功で失効するため、2 台目は TermWatch を再起動せずには接続できない。
   2 台での確認が必要な場合は、同じブラウザの別タブ（Cookie 共有）で行う。
2. 1 台目で操作モードを有効化する。
3. 2 台目で操作モードを有効化しようとする。

**期待結果**: 2 台目は「他の端末が操作モード中」と表示され、操作権を取得できない。
1 台目が解除すると 2 台目が取得できる。

---

## MT-13: スマートフォン接続で PC 側の端末サイズが変わらない

1. PC 側ターミナルの列数・行数を記録する（`$Host.UI.RawUI.WindowSize` など）。
2. iPhone で接続し、縦向き・横向きを切り替える。
3. PC 側のサイズを再確認する。

**期待結果**: PC 側のサイズは変化せず、Codex の描画も崩れない。
iPhone 側は縮小・折り返し・横スクロールで対応する。

---

## MT-14: ZIP 展開後、Node.js 無しで起動できる（別 PC）

1. `dist\TermWatch-win-x64.zip` を **Node.js がインストールされていない** Windows x64 PC へコピーする。
2. 任意のフォルダーへ展開する。
3. `termwatch.cmd -- cmd /c dir` などを実行する。

**期待結果**: 追加インストールなしで起動し、PTY 経由でコマンドが実行できる。
`node-pty` のネイティブモジュールが ABI 不一致で失敗しない。

**注記**: 開発機（Node.js v24.14.0 導入済み）での展開・実行は確認済み。
**Node.js 未導入の別 PC での確認は未実施。**

## MT-15: 障害系

| 項目 | 手順 | 期待結果 |
|---|---|---|
| ポート競合 | 43821 を使う別プロセスを起動してから TermWatch を起動 | 「ポート 43821 は既に使用されています」と表示して終了（自動変更しない）。子プロセスは起動しない |
| 転送停止 | 接続中に VS Code の Ports から転送を削除 | iPhone は「再接続中（経過時間）」表示のまま無期限に再試行し、30 秒を超えると警告色になる。子プロセスは継続。※「PC未接続」は子プロセス終了時の表示であり、通信断では出ない（D-021） |
| アカウント認証失敗 | 別アカウントで転送 URL を開く | dev tunnels 側で拒否され、TermWatch の画面に到達しない |
| dev tunnels 遮断 | 組織ポリシーで禁止された環境で試す | 転送自体ができない。TermWatch は LAN 公開へフォールバックしない |
| 子プロセス異常終了 | Codex をタスクマネージャーから強制終了 | 終了コードが PC 側・iPhone 側に表示され、TermWatch も終了する |
| TermWatch 強制終了 | TermWatch のプロセスを強制終了 | 子プロセスが孤児として残らない |
| 低速通信 | iPhone を低速回線にする | 表示は遅れるが TermWatch のメモリが増え続けない。追いつくとスナップショットで復帰 |
| バッファ上限 | `--buffer-lines 200` で大量出力 | 古い出力が破棄され、再接続時に truncated 通知が出る |

## MT-16: ログ保存に関する確認

1. `--record` を付けずに TermWatch を起動し、しばらく使ってから終了する。
2. プロジェクトフォルダーと `%TEMP%` に出力ログが作られていないことを確認する。
3. `--record out.log` を付けて起動し、`out.log` が作られることを確認する。
4. `out.log` にペアリングコードとセッショントークンが含まれないことを確認する。

**期待結果**: 既定ではディスクへ保存されない。`--record` 指定時のみ生 PTY 出力が保存され、
その中にも認証情報は含まれない。

---

## MT-17: iOS のソフトウェアキーボード表示

1. iPhone を縦向きにし、操作モードでテキストエリアをタップする。
2. キーボード表示中に画面を確認する。

**期待結果**: 入力欄が隠れず、ターミナルの現在行も見える。レイアウトが崩れない。
幅 320px 相当（iPhone SE 等、あるいはブラウザのレスポンシブモード）でも主要操作ができる。
